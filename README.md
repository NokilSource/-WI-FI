# System Repair · Windows x64

Локальная утилита диагностики и восстановления настроек Windows 10/11 x64.
Строгий табличный интерфейс на русском языке: выбор исправлений, диагностика
автозагрузки/служб/процессов и подробный журнал операций. Без телеметрии,
облачного анализа и автоматического удаления «подозрительных» объектов.

**Это не антивирус.** Отличие от типовой настройки не доказывает заражение.
Программа не удаляет вредоносное ПО и не гарантирует, что оно не вернёт изменения.
Сначала работайте в тестовой Windows VM со снимком; на рабочем компьютере
сохраняйте важные данные отдельно.

## Запуск и сборка

Требуются Windows x64, Python 3.12 x64 и [uv](https://docs.astral.sh/uv/getting-started/installation/).
В PowerShell из каталога проекта:

```powershell
uv sync --frozen
uv run system-repair
```

Обычный запуск разрешает диагностику. Для исправлений закройте программу и
запустите PowerShell/приложение **от имени администратора под тем же пользователем**.
При запуске от другого аккаунта HKCU относится к тому аккаунту, а не к исходному.
Программа не меняет UAC, антивирус и права доступа для обхода запретов.

```powershell
# Переносимая сборка; Python у конечного пользователя не нужен.
powershell -File scripts/build.ps1
```

Результат: `dist/SystemRepair-windows-x64.zip`. Распакуйте весь архив и запустите
`SystemRepair/SystemRepair.exe`. Подпись Authenticode не добавляется автоматически;
SmartScreen может показать предупреждение. Не отключайте защиту Windows ради запуска.
GitHub Actions также собирает ZIP после тестов: **Actions → Tests and Windows build →
успешный запуск → Artifacts → SystemRepair-windows-x64**. Наличие workflow не означает,
что сборка уже прошла: проверяйте статус конкретного запуска.

Для ознакомления без доступа к Windows:

```sh
uv sync --frozen --group dev
uv run system-repair --demo
```

Режим **ДЕМО** использует только синтетические данные в памяти, явно помечен в окне
и не вызывает Windows API/реальные процессы. Бэкапы демонстрации записываются
отдельно и не могут быть восстановлены в настоящую систему. На Linux запуск
без `--demo` запрещён. Это нативное Qt-приложение, не веб-сайт: HTTP Preview отсутствует.

## Рабочий процесс

1. Нажмите **«Проверить»**: реестр, hosts, Run/RunOnce, Winlogon, IFEO, службы и процессы
   только читаются. Жёлтый статус означает необходимость ручной проверки.
2. Отметьте необходимые исправления. По умолчанию не выбрано ничего.
3. **«Создать бэкап»** сохраняет выбранные разделы и сетевую конфигурацию без правок
   и без расходования суточного лимита точек восстановления.
4. **«Исправить выбранное»** показывает подтверждение и **всегда создаёт новый бэкап**,
   даже если раньше уже был сделан ручной. Ошибка любого обязательного этапа бэкапа
   блокирует весь набор исправлений. При выбранном сбросе сети здесь также
   создаётся и проверяется новая точка восстановления Windows.
5. После записи программа перечитывает значения/hosts. Ошибка останавливает
   последующие операции, но уже выполненные изменения не отменяются молча.
   В журнале указан путь к бэкапу. Внутри одной операции возможен частичный результат.
6. **«Восстановить бэкап…»** принимает `backup.json` с этого компьютера и пользователя.
   Перед откатом также сохраняется текущее состояние.

Не снимайте административные ограничения на управляемом компьютере без разрешения
его администратора. Доменные политики/MDM могут восстановить значения; программа
не отключает управление и не переписывает Group Policy.

## Модули

| Раздел | Реализация и границы |
| --- | --- |
| Системные политики | Удаление выбранных `DisableTaskMgr`, `DisableRegistryTools`, `DisableCMD`, `NoFolderOptions`, `NoRun` в HKCU/HKLM, 64-битное представление |
| Проводник | `Hidden=1`, `ShowSuperHidden=1` (DWORD) в HKCU; файлы не удаляются |
| Прокси | `ProxyEnable=0`, удаление `ProxyServer` и `AutoConfigURL` (PAC) текущего пользователя. WinHTTP, WPAD, GPO/MDM и настройки браузеров отдельно не изменяются. Перезапустите использующие прокси приложения |
| hosts | Побайтовый бэкап; удаление **всех** активных записей, включая легитимные. Итог — комментарии стандартного назначения localhost, который разрешается Windows без записей hosts. ACL существующего файла сохраняется; reparse points не обрабатываются |
| WinSock / TCP/IP | Только фиксированные команды `netsh winsock reset` / `netsh int ip reset <log>`, без shell. Требуются бэкапы конфигурации и успешная точка восстановления, затем перезагрузка. Автоматической перезагрузки нет |
| Автозагрузка | Чтение Run/RunOnce в HKCU/HKLM, представления 32/64 bit. Winlogon Userinit/Shell сравниваются с типовым значением, не исправляются автоматически |
| IFEO | Чтение настроек `cmd.exe`, `regedit.exe`, `taskmgr.exe`, включая вложенные фильтры, в обоих представлениях реестра. Перехваты не удаляются автоматически |
| Службы | Имя, путь, состояние, тип запуска и аккаунт; только чтение |
| Процессы | PID, имя, путь, аккаунт; путь в Temp/AppData — повод проверить, а не диагноз. Завершение только выбранного PID после подтверждения. Проверяются время создания, путь и критичность на одном WinAPI handle; системные, собственные и родительские процессы защищены |

**Сброс сети может оборвать RDP/VPN и сбросить статические IP/DNS.** Не выполняйте
его удалённо. Если защита системы отключена, создание точки запрещено политикой
или Windows не подтвердила её создание, сброс не выполняется. Код возврата `netsh=0`
не гарантирует успех каждого внутреннего компонента: прочитайте его вывод и
проверьте связь после перезагрузки.

## Резервные копии и откат

По умолчанию: `%LOCALAPPDATA%\SystemRepair\Backups\<UTC-время>-<идентификатор>\`.
Можно явно задать `--backup-dir <каталог>`. Содержимое может включать внутренние
адреса, пути и другие конфиденциальные данные; храните его в защищённом локальном
каталоге, не публикуйте и не отправляйте в общие облачные папки.

- `backup.json` — версия формата, идентификаторы машины/SID пользователя, список
  операций, исходные значения **с типами** или отметка об отсутствии.
  Появляется только после успешного завершения обязательных этапов бэкапа.
- `branches.json` — рекурсивные снимки затрагиваемых веток, включая подветки;
  типы, бинарные данные (base64), DWORD/QWORD, MULTI_SZ и отсутствие ключа сохранены.
- `hosts.bin` — исходные байты, если файл существовал; SHA-256 хранится в манифесте.
- `network.json` — вывод netsh dump (IPv4/IPv6/WinSock) и `ipconfig /all`, если выбран
  сброс стека. Номер точки Windows находится в манифесте бэкапа перед применением;
  у отдельного ручного бэкапа он отсутствует.

Автоматический откат **не импортирует целую ветку поверх текущих настроек**:
восстанавливаются только известные приложению изменённые значения и hosts.
Ранее отсутствовавшие значения удаляются; пустые созданные ключи могут остаться.
Неизвестные операции/адреса, чужой компьютер/SID, неверные типы и повреждённый hosts
блокируют откат. Бэкап — локальные данные, а не криптографически подписанный архив;
не используйте полученные от посторонних файлы.

**Сетевой стек не откатывается простым импортом реестра.** Для него используйте
созданную точку через `rstrui.exe` и сохранённую конфигурацию. Завершённый процесс
и его несохранённые данные восстановить бэкапом нельзя. Бэкап выбранных настроек
не заменяет образ диска и не является атомарной транзакцией всей ОС.

## Архитектура

**Python + PySide6** выбран для нативных плотных таблиц Qt и проверяемого отделения
интерфейса от системных вызовов. `winreg` обращается к Windows Registry API;
`ctypes` — непосредственно к WinAPI (SID, критичность и работа с process handle).
`psutil` читает процессы и SCM-службы, не классифицируя их как вредоносные.
Точка восстановления создаётся штатным Windows PowerShell `Checkpoint-Computer`;
через `Get-ComputerRestorePoint` проверяется появление **нового** номера с уникальным
описанием. Суточный лимит Windows, отключённая защита или запрет PowerShell блокируют
сброс сети; приложение не меняет лимит, ExecutionPolicy или настройки защиты.

```text
system_repair/
  catalog.py       разрешённые операции и фиксированные адреса реестра
  model.py         типизированные значения, результаты, контракт Platform
  windows.py       WindowsPlatform: winreg, WinAPI, hosts, netsh, процессы/службы
  demo.py          DemoPlatform: изолированные синтетические данные
  backup.py        BackupStore: снимки, проверка формата/принадлежности
  inspection.py    диагностика Run/RunOnce, Winlogon, IFEO
  engine.py        RepairEngine: бэкап → изменение → чтение-проверка; откат
  ui.py            MainWindow и фоновые задания с Qt-сигналами журнала
  __main__.py      явный выбор Windows/демо, каталог бэкапов
tests/             безопасные модульные, GUI и Windows-адаптерные проверки
scripts/build.ps1  сборка переносимого Windows x64 ZIP
```

GUI не содержит команд реестра. Единственное рабочее задание выполняется в фоне;
повторный запуск операций и закрытие окна на середине записи запрещены. Все
исправления проходят через `RepairEngine` / `BackupStore`; создание старого
ручного бэкапа не даёт возможности обойти новый бэкап.

## Проверки

```sh
uv sync --frozen --group dev
uv run ruff check .
# Для Linux без дисплея:
QT_QPA_PLATFORM=offscreen uv run pytest -q
QT_QPA_PLATFORM=offscreen uv run system-repair --demo --smoke-test
```

На Linux системная зависимость Qt — `libegl1`; `bash scripts/setup.sh` устанавливает
её при доступных правах и повторяемо проверяет запуск Qt. На Windows:
`uv run pytest -q`. Windows-тесты используют только временные ключи
`HKCU\Software\SystemRepairTests\<uuid>` и собственные тестовые дочерние процессы;
рабочие политики, hosts и сетевой стек тестами не изменяются.

Перед эксплуатацией в одноразовой Windows VM вручную проверьте: отказ в правах,
успешный/неуспешный бэкап, применение и откат политик, защищённый hosts, создание
точки восстановления, сброс сети и перезагрузку. Проверки демо не заменяют этот этап.

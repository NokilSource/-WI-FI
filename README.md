# System Repair 0.2 · Windows x64

Локальное настольное приложение для диагностики Windows 10/11 x64, проверки
настроек и восстановления выбранных параметров. Интерфейс на PyQt6; psutil,
pywin32, Windows API и штатный PowerShell используются только для конкретных
операций приложения. Нет облачного анализа, телеметрии или автоматического
удаления объектов по эвристике.

**Это не антивирус и не полноценный образ системы.** Необычный путь, отсутствие
подписи или отличие настройки от типовой — повод для проверки, не доказательство
заражения. Сначала проверьте программу в одноразовой Windows VM и сохраните важные
данные отдельно.

## Требования и запуск

Для Windows нужны 64-разрядная Windows 10/11, Python 3.12 x64 и
[uv](https://docs.astral.sh/uv/getting-started/installation/). Из PowerShell в
корне репозитория:

```powershell
uv sync --frozen
uv run system-repair
```

Обычный запуск предназначен для чтения и аудита. Изменение реестра, автозагрузки,
задач, служб и файлов, а также системные операции требуют прав администратора и
отдельного подтверждения (кроме открытия оснастки «Управление дисками» и настроек темы).
Для HKCU запускайте приложение с повышением прав под тем же пользователем:
HKCU другого аккаунта — другой профиль. Программа не снимает политики доступа, не
обходит UAC и не изменяет настройки Windows Defender.

На других ОС доступна только синтетическая демонстрация:

```sh
uv sync --frozen --group dev --group build
uv run system-repair --demo
```

**Демо не обращается к Windows API и настоящим процессам, реестру, задачам,
службам или файлам.** Все показываемые объекты синтетические; журнал и демонстрационные
резервные записи при действиях всё же записываются локально в каталог бэкапов.
Не направляйте их в общую или сетевую папку. `--smoke-test` разрешён только вместе
с `--demo`.

## Сборка Windows-приложения

Сборка выполняется на Windows x64 с Python 3.12 x64 и установленным `uv`:

```powershell
# Режим по умолчанию — один переносимый EXE
powershell -File scripts/build.ps1

# Альтернативно — папка приложения с отдельными библиотеками
powershell -File scripts/build.ps1 -Mode onedir
```

Скрипт собирает выбранный режим и запускает упакованное приложение в безопасном
демо-smoke-тесте. Предусмотренные архивы:

- `dist/SystemRepair-windows-x64-onefile.zip` — `SystemRepair.exe` в корне архива;
- `dist/SystemRepair-windows-x64-onedir.zip` — `SystemRepair/SystemRepair.exe` и
  вся папка `SystemRepair/`, включая `_internal`.

Оба архива также содержат `README.md`, `THIRD_PARTY.md`, `LICENSE-SYSTEM-REPAIR`,
каталог `licenses/` и `SystemRepair-source.zip` с исходниками именно той версии,
которая собиралась, и полной лицензией GPLv3. В режиме `onedir` не отделяйте EXE
от его `_internal`. Подпись Authenticode автоматически не добавляется; Windows
может показать предупреждение SmartScreen. Не отключайте защиту системы ради запуска.

Скрипт сборки Windows-only и откажется работать на Linux. GitHub Actions настроен
проверять проект на Linux и Windows, а запускать PyInstaller-сборку и smoke test обоих
режимов — на `windows-latest`. Linux job не заявлен как сборка приложения для Linux
или как способ получить Windows exe. Это описание конфигурации, не утверждение об
успехе какого-либо запуска или наличии готового архива: перед распространением
проверьте статус конкретного запуска Actions и скачивайте только его фактический
артефакт.

## Рабочий процесс и резервирование

Сканирование само по себе ничего не исправляет. Каждый объект надо проверить; для
опасных изменений интерфейс отдельно запрашивает подтверждение. Перед изменением
реестра, задачи, службы или карантином файлов движок сохраняет соответствующий
локальный снимок/манифест и сверяет актуальные данные с результатом сканирования.
Ошибка записи обязательного снимка блокирует эту мутацию.

Путь по умолчанию — `%LOCALAPPDATA%\SystemRepair\Backups`; `--backup-dir <каталог>`
позволяет указать другой. Путь проверяется перед записью: в Windows UNC/device/ADS
и пути через символьную ссылку или reparse point отклоняются. Выбирайте защищённый
частный локальный каталог, не общую папку, сетевой ресурс или синхронизируемое
облачное хранилище. В резервных файлах могут оказаться пути, команды запуска, ветви
реестра и внутренние сведения системы.
Храните их как конфиденциальные данные.

Есть два вида снимков:

- основной бэкап выбранных исправлений: `backup.json`, типизированные значения и
  снимки затронутых ветвей реестра, `hosts.bin`, а для сброса сети — сохранённая
  конфигурация. Новая подтверждённая точка восстановления обязательна перед
  применением сброса сети; ручной бэкап сам по себе её не создаёт;
- журнал аудита `actions/`: снимки перед отдельными редакторскими операциями,
  XML/SDDL задачи, SCM-конфигурация/описание/состояние/SDDL службы и, для удаления,
  полный типизированный снимок её ветви реестра; данные офлайн-куста и манифесты
  карантина с хешем содержимого.

Форматы привязаны к идентификаторам компьютера и пользователя (включая SID):
восстановление из бэкапа другого компьютера, SID или режима демо/Windows не разрешается.
Это проверка совместимости, а не криптографическая подпись: используйте только
доверенные локальные снимки, не чужие JSON/бинарные файлы. Автоматический
откат ограничен данными известной операции; он не импортирует целые ветви «поверх»
системы и не отменяет произвольные побочные эффекты. Пакетные файловые действия
могут завершиться частично: ранее обработанные файлы автоматически не возвращаются.
Завершение процесса, его несохранённые данные и приостановка процесса не отменяются
бэкапом. **Ни один из этих механизмов не является полной резервной копией, образом
диска или транзакцией всей Windows.**

## Возможности и ограничения

### Процессы

Снимок включает PID/родителя, имя, время запуска, издателя, путь, аргументы командной
строки, пользователя и результат Authenticode-проверки. Доступны поиск, группировка
одинаковых путей, фильтры «Скрыть доверенные системные», «Подозрительные» и
«С цифровой подписью», переход к файлу и поиск дубликатов. В эвристику подозрительности
входят, например, пользовательские/Temp и скрытые пути. Доверенность и подозрительность
не являются вердиктами; Authenticode проверяется штатным PowerShell, а неизвестная
подпись не равна вредоносной.

Флаг **Critical только для чтения**: менять критичность процесса приложение не
пытается. Завершение, приостановка и возобновление требуют административной проверки
идентичности процесса; защищённые системные, собственные и родительские процессы
отклоняются. Завершение дерева требует отдельного подтверждения фиксированного
неизменяемого плана PID/пути/времени запуска: все процессы и дескрипторы
перепроверяются до первой остановки, дети завершаются раньше родителей. Новые
процессы, появившиеся после планирования, в подтверждённый список не добавляются. Это не
атомарная отменяемая операция: после начала завершения возможен частичный результат.
Убийство/приостановка процесса не восстанавливается из снимка. Приостановка вызывает
`NtSuspendProcess`/`NtResumeProcess` из `ntdll` — это недокументированные внутренние
NT API, не публичный контракт Windows. При ошибке приостановки реальное состояние
может быть неопределённым; утилита удерживает дескриптор, чтобы позволить попытку
возобновления. Обычное закрытие пытается освободить удерживаемые ресурсы, но это
best-effort, а не гарантия. При принудительном завершении приложения, аварии Windows
или BSOD очистка не гарантируется; список дескрипторов не переживает перезапуск.

### Автозагрузка и реестр

Аудит читает HKCU/HKLM Run/RunOnce, Winlogon, BootShell и физические папки Startup
пользователя и ProgramData; проверяются 32- и 64-битные представления там, где они
имеются. Shell/Userinit сравниваются с типовыми значениями; IFEO проверяется для
`cmd.exe`, `regedit.exe` и `taskmgr.exe`, включая вложенные фильтры. Автоматических
исправлений нет. Запись автозапуска реестра сохраняет исходное типизированное
значение, а файл Startup помещается в карантин, а не принудительно удаляется.

Редактор реестра показывает ключи HKCU/HKLM и 32-/64-разрядные представления; поддерживает
REG_SZ, REG_EXPAND_SZ, REG_BINARY, DWORD, QWORD и MULTI_SZ. Добавление, изменение и
удаление значения требуют подтверждения и манифеста до записи. Снимок содержит старое
типизированное значение и ветвь; точечное восстановление манифеста `registry-value`
доступно по кнопке **«Восстановить action.json…»** на вкладке «Реестр».
Если значение изменилось после исходной операции, откат отклоняется.
Это не кнопка глобального отката всех действий.
Защищённые ветви учётных данных и Windows Defender редактором не изменяются.

Офлайн-куст можно подключить к текущему HKLM **как рабочую копию**: исходный файл
сначала сохраняется отдельно и не перезаписывается; все изменения относятся только к
`working.hiv`. До загрузки куста в `actions/<идентификатор>/action.json` сохраняются
`payload.mount_key` (`SystemRepairOffline_<uuid>`), относительные имена
`original.hiv`/`working.hiv` и `payload.owner_pid`. При обычном закрытии приложение сначала должно успешно
возобновить отслеживаемые процессы и выгрузить подключённые кусты; до завершения
очистки окно остаётся открытым, а при её ошибке не закрывается. Перезагрузка в
WinRE/Safe Mode/UEFI также не запускается, пока эта очистка не завершена.

Если приложение аварийно завершилось после `RegLoadKey`, ключ
`HKLM\SystemRepairOffline_<uuid>` может остаться подключённым. Найдите запись
`action.json` и используйте сохранённый `payload.mount_key`, чтобы вручную выгрузить
его через Regedit. Автоматического восстановления или копирования поверх исходного
куста нет. Кусты `SAM`/`SECURITY` не поддерживаются. Нужны загруженная Windows, права
и привилегии backup/restore; это не WinRE-среда, не запуск из WinRE и не обещание
полного автономного восстановления системы. Пользователь сам отвечает за дальнейшее
применение выгруженной копии.

### Планировщик заданий

Дерево Планировщика включает папки Microsoft, сторонних поставщиков и пользователя.
Для доступных (в том числе скрытых) задач отображаются автор, описание, даты,
команда/действие, состояние и XML. Включение/отключение требует
подтверждения. Перед изменением или удалением сохраняются XML задачи и её SDDL,
проверяется, что задача не изменилась после сканирования. Задачи в
`\\Microsoft\\Windows\\` защищены от изменений. Автоматического восстановления
задачи нет: при ручном восстановлении может потребоваться импорт XML, повторное
назначение SDDL и ввод учётных данных — **пароли в снимок не включаются**.

### Службы

Список SCM включает системное/отображаемое имя, PID, описание, команду, учётную запись,
режим запуска, состояние и Authenticode-статус. Фильтр подозрительности отмечает,
например, отсутствующее описание, путь пользовательского профиля или некорректную
подпись; это повод для проверки, а не вердикт о заражении. Административные действия:
запуск, остановка, Авто/Вручную/Отключена и удаление.

Перед действием журналируются `QueryServiceConfig` от SCM, описание, состояние и
SDDL; актуальность проверяется повторно. Для удаления дополнительно сохраняется
полное рекурсивное содержимое `HKLM\SYSTEM\CurrentControlSet\Services\<имя>`:
значения с исходными типами и дерево дочерних ключей. Если этот снимок не удаётся
получить или он меняется, удаление отменяется. Драйверы, системные и защитные службы, Defender и
образы из системных каталогов Windows защищены. Зависимые службы не останавливаются
автоматически; удалить можно только остановленную службу без активных зависимых.
SCM может пометить удалённую службу как `MARKED_FOR_DELETE`; приложение ограниченно
проверяет завершение удаления и при тайм-ауте сообщает, что оно осталось ожидающим,
а не подтверждает успех. Автоматического восстановления SCM или сохранённой ветки
реестра нет. Для ручного воссоздания службы пароль учётной записи нужно ввести
заново — он в резервную копию не включается.

### Файлы

Анализируется только явно выбранный локальный каталог. Сканер ограничивает проход
20 000 элементами, 5 000 результатами и 30 секундами; хеширование/копирование одного
файла ограничено 512 MiB. При достижении предела результат помечается неполным.
Точные дубликаты определяются SHA-256; похожее имя не означает совпадение содержимого.
Доступны пакетное копирование, карантин и восстановление из карантина для выбранных
1–200 файлов.

Принудительного удаления заблокированных файлов нет. В Windows карантин читает,
хеширует, копирует и помечает на удаление исходный файл через один удерживаемый
нативный дескриптор: это защищает от подмены пути между проверкой и удалением.
Карантин запрещён для защищённых системных каталогов/бэкапов, ADS, EFS, hard links и
неподдерживаемых объектов; симлинки и reparse points пропускаются/отклоняются.
UNC/device namespace и пути к потокам ADS отклоняются. Копия перед карантином проверяется по SHA-256;
операция не обещает сохранение ACL, ADS или EFS-метаданных. Восстановление не
перезаписывает существующий путь и не запускает файл.

### Восстановление и системные действия

Доступны только явные исправления с резервированием до записи:

- снять выбранные ограничения Task Manager, Registry Editor, CMD, Run и параметров
  папок; показать скрытые системные файлы;
- включить UAC (`EnableLUA=1`) с предупреждением о перезагрузке — отключения UAC нет;
- снять политики `NoDrives`/`NoViewOnDrive`, скрывающие диски; разрешение NTFS и
  содержимое диска не изменяются;
- частично восстановить ассоциации `.exe`, `.bat`, `.lnk`, `.reg` только для HKCU;
  `UserChoice`, политики и настройки других пользователей не обходятся;
- разрешить запуск оснастки `gpedit` удалением её `Restrict_Run`. Утилита не
  устанавливает `gpedit.msc` в Windows Home и не обходит доменную/MDM-политику MMC;
- для внешнего вида открыть штатные настройки темы; принудительного сброса шрифтов нет.

`SFC /scannow` запускается только после создания и проверки новой точки восстановления;
если точка не подтверждена, SFC не стартует. SFC может изменить защищённые файлы
Windows, а его результат надо проверить отдельно — журнал действия не отменяет SFC.
Доступны управление дисками и подтверждаемые системные команды перезагрузки:
WinRE, экран дополнительных параметров для выбора Safe Mode и UEFI/BIOS на
совместимом компьютере. Для этого используется обычный `shutdown.exe`; постоянные
изменения BCD не вносятся. Safe Mode не включается незаметно: после перезагрузки его
надо выбрать в меню Windows. Сохраните работу и учитывайте, что удалённое соединение
оборвётся.

### Сетевые исправления

В приложении также остались явные бэкапируемые операции для пользовательского прокси,
hosts, WinSock и TCP/IP. Сброс hosts удаляет все активные записи, включая легитимные;
сброс WinSock/TCP/IP требует успешной точки восстановления и последующей перезагрузки;
приложение не перезагружает компьютер автоматически. Сброс может изменить статические
IP/DNS, VPN и RDP. Не выполняйте сетевой сброс удалённо.
Сеть не откатывается импортом JSON/ветвей реестра: используйте созданную точку
Windows через `rstrui.exe` и сохранённую сетевую конфигурацию.
Пользовательский прокси не меняет WinHTTP, WPAD, браузеры или управляемые политики.
Код завершения штатной команды не заменяет проверку её вывода и результата.

## Архитектура

```text
system_repair/
  audit_ui.py        страницы процессов, автозагрузки, реестра, задач, служб и файлов
  audit.py           движок аудита, проверка полномочий, интеграция журналов действий
  audit_model.py     типизированные записи аудита
  processes.py       psutil, Authenticode, управление процессами и фиксированный KillTree
  task_service.py    COM Task Scheduler, SCM pywin32, проверка/резервирование операций
  registry_audit.py  редактор, точечные бэкапы и подключение офлайн-кустов
  files.py           ограниченный файловый поиск, копирование, карантин и восстановление
  windows_files.py   карантин Windows через один проверяемый файловый дескриптор
  catalog.py         перечень явно разрешённых системных исправлений
  engine.py          основной движок исправлений и бэкапов
  windows.py         Windows API, реестр, hosts, сеть и точка восстановления
  journal.py         проверяемые локальные снимки отдельных действий
scripts/
  build.ps1          onefile/onedir сборка, сбор лицензий и подходящих исходников
```

`WiFi.bat` остаётся отдельным прежним файлом в корне репозитория: это не часть
приложения, не вызывается им, не включается в exe/архивы и не изменяется этой сборкой.

## Проверки

```sh
uv sync --frozen --group dev --group build
uv run ruff check .
QT_QPA_PLATFORM=offscreen uv run pytest -q
QT_QPA_PLATFORM=offscreen uv run system-repair --demo --smoke-test
```

Группа `build` нужна и для `tests/test_packaging.py`: этот тест проверяет сбор
лицензий зависимостей упаковки. Команда инициализации для демонстрации/проверок
использует те же группы: `uv sync --frozen --group dev --group build`.
Linux-запуск Qt может требовать системную библиотеку `libegl1`; `bash scripts/setup.sh`
устанавливает её при доступных правах. Модульные проверки используют синтетические
SCM/COM и временные данные; проверка нативного Windows-аудита — только чтение.
Тесты реестра используют изолированный ключ HKCU и не изменяют реальные задания,
службы, сетевой стек или системные политики. На Windows CI запускает реальные
упакованные Windows onefile/onedir-приложения в demo smoke test; этот документ не
подтверждает статус конкретного CI-run. Проверки `--demo` не заменяют ручной
контроль в одноразовой Windows VM.

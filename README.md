# AegisKit 1.3

**AegisKit** — утилита для глубокой системной диагностики, аудита безопасности и восстановления Windows (аналог Process Hacker / AVZ), написанная на **C# / WPF (.NET 8)** в тёмной теме с плоским дизайном.

Проект создан с опорой на архитектуру и реестровые техники открытого инструмента **RecoveryKit** (Delphi/VCL): его исходный код использован как образец (`Source/DefenderUtils/*` — модули снятия блокировок, `Source/ProcessTree` — работа с NtAPI, `Source/Regedit/uRegistryHiveLoader.pas` — монтирование offline-кустов) и переработан в современную модульную архитектуру.

## Что нового в 1.3

### Интерфейс
- **Главное меню** (Файл / Действие / Окно / Справка) вместо одной строки с журналом слева.
- **Журнал переехал вниз** — отдельная панель на всю ширину с ползунком высоты, кнопками «Сохранить в файл…», «Очистить», «Свернуть» и **индикатором хода выполнения** (проценты + подпись текущей операции).
- **Верхняя панель инструментов больше не наезжает** друг на друга: кнопки и фильтры собраны в `WrapPanel` и переносятся на новую строку вместо наложения. Поля поиска получили собственную рамку с подсказкой внутри — раньше подсказка рисовалась отдельным элементом поверх поля и могла «съехать».
- **Столбцы таблиц двигаются и растягиваются мышью.** Ширины столбцов заданы в пикселях, а не звёздочками: раньше таблица «вписывалась» в окно, сжимая колонку с путём до нуля, и горизонтальной прокрутки не было — столбцы выглядели нерастягиваемыми. Появились видимые ручки-разделители, стрелка сортировки и горизонтальная прокрутка; **ширина столбцов сохраняется** между запусками (`%LOCALAPPDATA%\AegisKit\settings.json`).
- **Меню переделано целиком**: свои шаблоны для всех ролей `MenuItem`, тёмное подменю с рамкой вместо системного светлого прямоугольника с чужой полосой выделения.
- **Иконки у пунктов навигации убраны** — остался только текст с акцентной полосой.
- **Мультивыделение работает везде**: удаление, запуск и остановка применяются ко всем выделенным строкам (автозагрузка, планировщик, службы, процессы, файлы), а не по одной.
- **Текст в ячейках больше не выезжает в соседний столбец** — `ClipToBounds` на ячейке плюс полный текст в подсказке при наведении.
- **Изменённые системные объекты выделяются красным**: записи Winlogon (`Shell`, `Userinit`, `UIHost`, `Taskman`, `AppSetup`), `BootExecute`, IFEO Debugger, `AppInit_DLLs`, пакеты LSA, `Winlogon\Notify`, `ServiceDll`, `CmdLine` — а также все подозрительные процессы, задачи и службы. Причина объясняется в подсказке и в пункте «Почему помечено…».
- **«Поверх всех окон»** — галочка в шапке и пункт меню «Окно»; состояние сохраняется.
- Убраны пиктограммы-«смайлики»: в списке разделов и в контекстных меню нет символьных глифов — важно для WinRE, где наборы шрифтов урезаны.
- Диалог ввода значений реестра стал тёмным (раньше оставался светлым), Enter подтверждает, Shift+Enter переносит строку.
- Горячие клавиши: **F5** — обновить раздел, **Ctrl+L** — очистить журнал, **Ctrl+S** — сохранить журнал.

### Реестр
- **Путь показывается как путь**: `Компьютер\HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\…` вместо короткого `HKLM`, плюс **навигационная строка с кликабельными сегментами** («хлебные крошки») и кнопка «Вверх».
- Кнопки переименованы в понятные: **«Подключить куст реестра…» / «Отключить куст» / «Проверить офлайн-систему»** (было «Монтировать куст / Выгрузить куст / Аудит куста»).
- **«Отключить куст» недоступна, пока ни один куст не подключён**; вместо диалога с вводом номера — список подключённых кустов (`ComboBox`).
- При старте открывается раздел, у которого точно есть параметры (пустой `HKLM\SOFTWARE` выглядел как «реестр не работает»).

### Восстановление
- **Кнопка «Восстановить всё»** — один клик снимает все выбранные ограничения по порядку, с подтверждением и списком того, что будет сделано.
- **Выбор пунктов галочками** (37 пунктов в 5 группах) с кнопками «Отметить всё», «Снять всё», «Только изменённое»; выбор сохраняется между запусками.
- Отдельная кнопка **«Только отладчики и перехваты»**.
- **Разблокировка отладчиков сделана как в RecoveryKit и шире**: в IFEO удаляются не только `Debugger`, но и `GlobalFlag`, `VerifierDlls`, `FilterFullPath`, `MitigationOptions`, `MinimumStackCommitInBytes`, `TracingFlags` — в **HKLM и HKCU**, в **обоих представлениях реестра**; легитимные отладчики (VS JIT, Application Verifier, WinDbg) не удаляются.
- Добавлены операции, которых не было: `DisallowRun`/`RestrictRun` с очисткой подключей, `DisableCAD`, кнопка питания (`NoClose`, `DisablePowerButton`), подавление курсора, `NoDeviceManagerPage`, панель задач и меню «Пуск», выход из системы, быстрая смена пользователя, `NoTaskSwitching` (Alt+Tab), политики учётных записей и автовход (`AutoAdminLogon`/`DefaultPassword`), перехват `SYSTEM\Setup\CmdLine`, подмена клавиш (`Scancode Map`) и раскладки RU/EN, `AppInit_DLLs`, посторонние пакеты LSA, `Winlogon\Notify`, восстановление `Shell`/`Userinit`/`UIHost`, `BootExecute`.
- **Отдельная панель «Инструменты»**: проводник дисков, Regedit, диспетчер задач, командная строка, services.msc, управление дисками, msconfig, параметры папок, шрифты, тема, ассоциации, перезапуск Проводника.
- **SFC/DISM с прогрессом**: проценты DISM разбираются из вывода и показываются в журнале; для `sfc /scannow` (он процентов не печатает) идёт бегунок. Вывод сохраняется в файл.

### Планировщик
- Список показывает задачи **выбранной папки** — по умолчанию корень (`\`), как в оснастке Windows и в RecoveryKit. Раньше в таблицу сразу попадали все папки, включая сотни задач `\Microsoft\…`, и «240 записей» выглядели ошибкой.
- Добавлен фильтр **«Показать все папки»** и колонка «Папка»; в сводке видно «Показано: N · всего задач: M».
- Дубликаты записей отбрасываются по полному пути.
- **Фолбэк на `schtasks.exe`** (`/query /xml ONE`): если PowerShell недоступен или заблокирован политикой (типично для WinRE), список всё равно читается — пути берутся из `<URI>`, поэтому разбор не зависит от языка системы.

### Файлы
- Страница стала настоящим **проводником**: список дисков, кнопки «Назад»/«Вверх» с историей переходов, кликабельная навигационная строка, создание папки, переименование, двойной клик — вход в папку, Enter — открыть, Backspace — вверх.
- Эвристика недавних файлов переехала на отдельную вкладку.

### Сборка и среда восстановления
- **Один самодостаточный EXE**: `build.cmd single` → `publish\AegisKit.exe` (≈63,5 МБ, один файл, без .pdb, .NET внутрь).
- **WinRE/WinPE**: при обнаружении среды восстановления включается программная отрисовка (`SoftwareOnly`) — без неё WPF-окно оставалось пустым; настройки пишутся в `%TEMP%`, а не в профиль пользователя; список процессов читается нативным снимком (без WMI); планировщик работает через `schtasks.exe`.
- **Исправлена настоящая ошибка, из-за которой не работала самопроверка**: `StartupUri = null` бросает `ArgumentNullException` в .NET 8 — окно создаётся теперь явно в `OnStartup`.

## Что исправлено в 1.2

Версия 1.1 собиралась и запускалась, но половина экранов выглядела «пустой». Причины и правки:

| Что было | Причина | Что сделано |
|---|---|---|
| Автозагрузка не показывала ни одной записи | `ObservableCollection` была заменена обычным списком — дерево/таблица не узнавали о подгрузке | Возвращён `ObservableCollection`, пересчитаны вердикты записей |
| Планировщик показывал **0 задач** | PowerShell писал JSON в консольной кодировке (CP866), `System.Text.Json` не разбирал байты | Вывод приведён к UTF-8 (`OutputEncoding`+`[Console]::OutputEncoding`), добавлен разбор одиночного объекта и объектов-обёрток: **177 задач** |
| `sfc`/`DISM` падали | `Encoding.GetEncoding(866)` бросает `NotSupportedException` без `CodePagesEncodingProvider` | Добавлен `Compat/CodePages.Oem` с регистрацией провайдера и HTML-фолбэком |
| Службы: пустой список | SCM открывался с правами только на чтение | `OpenSCManager` с `SC_MANAGER_ALL_ACCESS`, фолбэк на `SC_MANAGER_CONNECT \| ENUMERATE_SERVICE`: **242 службы** |
| «Белая полоса» из квадратов в колонке Critical/Вкл | Стандартный шаблон `CheckBox` рисует белый фон и светлую рамку | Свой тёмный шаблон флажка (`GridOnOff`), проверено рендером пикселей |
| Столбец «Вердикт» горел красным почти везде | Любое отсутствие подписи объявлялось подозрительностью | Двухуровневые признаки: сильные — «Подозрительно», слабые — «Без подписи»; каждый вердикт объясняется в подсказке |
| Редактор реестра «не работал» | Пустой список параметров у разделов без значений (например `HKLM\SOFTWARE`) выглядел как сбой; дерево подгружало подключи списком | Дерево на `ObservableCollection`, счётчик параметров и пояснение для пустого раздела, кнопка «Обновить», дерево и поле адреса синхронизированы |
| Сканирование недавних файлов шло минуту и почти ничего не находило | Однопоточный обход с жёстким потолком каталогов | Обход «волнами» в 2–8 потоков (12 с вместо 52 с), сортировка «подозрительные сверху», отсев служебных каталогов, признак снимается у подписанных файлов |
| Снимок процессов вытягивался через WMI | Не было нативного чтения | NtQuerySystemInformation + PEB (путь и командная строка), WMI остаётся фолбэком; снимок ~300 процессов ≈ 0,4 с |
| Монтирование offline-кустов не работало | `RegLoadKey` с неприподнятой привилегией создавал только корень монтирования | Полное монтирование через `RegCreateKeyEx` + `SeBackup/SeRestore`, появились операции с смонтированными кустами (создание/удаление ключей и параметров) |
| Файлы автозагрузки: пропущены `Wow6432Node`, AppInit, IFEO, LSA, Winlogon Notify | Сканировались только две ветки Run | Добавлены все точки персистентности (`AppInit_DLLs` 64/32, IFEO Debugger, LSA Packages, Winlogon Notify, RunOnceEx, политики Run) |

## Возможности

### 1. Диспетчер процессов
- Таблица: имя, PID, флаг **Critical**, издатель (CompanyName), полный путь, **командная строка** (через WMI), состояние потоков.
- Контекстное меню: **Kill**, **Kill Tree** (обход дерева по ParentPid снизу вверх), **Suspend/Resume** (`NtSuspendProcess`/`NtResumeProcess` из ntdll), **переключение флага критичности** (`NtSetInformationProcess` + `ProcessBreakOnTermination`), переход к папке, поиск дубликатов/похожих файлов в типичных местах.
- Фильтры: «Скрыть доверенные» (Microsoft/Intel/NVIDIA…), «Подозрительные» (запуск из %TEMP%/AppData, нет файла), «С подписью».
- Проверка **Authenticode** (`WinVerifyTrust`) — по одной строке или пакетно.

### 2. Аудит автозагрузки и реестр
- Сканирование: `HKLM/HKCU …\CurrentVersion\Run`, `RunOnce`, `RunOnceEx`, `Wow6432Node`, **политики Run**, **Winlogon** (`Shell`, `Userinit`, `Taskman`, `AppSetup`, `UIHost`), **BootExecute** (Session Manager), `AutoRun` командного процессора, физические **папки Startup** (пользовательская и ProgramData) с раскрытием .lnk.
- Четыре вкладки с прикладными названиями: **Run / RunOnce**, **Winlogon / Shell**, **AppInit / CmdLine / Перехваты**, **Папки автозагрузки**.
- **Колонка «Вердикт» убрана** — состояние записи видно по красной подсветке строки, а причина объясняется в подсказке и в пункте «Почему помечено…».
- **Колонка «Добавлено»**: время последней записи ключа реестра (`RegQueryInfoKey`) либо дата создания файла в папке автозагрузки.
- Понятные строки вместо «scecli = scecli»: пакет LSA и `Winlogon\Notify` показывают **полный путь к DLL**, `CmdLine` из `Session Manager\Setup` добавлен отдельным механизмом.
- Эвристика без ложных срабатываний: подпись учитывается только после проверки, служебные значения Command Processor игнорируются, голые имена (explorer.exe) разворачиваются в системные пути.
- Действия: удалить (для Shell/Userinit/BootExecute — **восстановление эталона**), редактировать, открыть ключ в штатном Regedit (через `LastKey`), перейти к файлу.
- **Встроенный редактор реестра**: ленивое дерево всех ульев, строка адреса с переходом, правка значений двойным кликом / Del, создание и удаление ключей и параметров (все типы REG_*).
- **Монтирование автономных кустов** (`RegLoadKey` с включением `SeBackupPrivilege`/`SeRestorePrivilege`) — анализ SYSTEM/SOFTWARE/SAM другой Windows-установки, работа из WinRE. Выгрузка через `RegUnLoadKey`. Быстрый аудит смонтированного SYSTEM-куста на подозрительные драйверы/службы.

### 3. Планировщик заданий
- Древовидная навигация по папкам задач, поля: имя, состояние, **следующий запуск**, **дата создания**, автор, команда, проблемы.
- **Чекбокс в строке** = включение/отключение задачи (`Enable-ScheduledTask`/`Disable-ScheduledTask`), удаление (`Unregister-ScheduledTask`), запуск, просмотр XML.
- Эвристика: команда из temp/AppData/Users, `powershell -hidden/-enc`, файл не найден.
- Бэкенд — встроенный PowerShell (ScheduledTasks, JSON-обмен с `-EncodedCommand`, асинхронное чтение stdout+stderr — без дедлоков буферов): 177 задач за ~3 с.
- Поиск по имени/команде/автору.

### 4. Менеджер служб
- Список через **SCM API** (`EnumServicesStatusEx` + `QueryServiceConfig`/`QueryServiceConfig2`): имя, отображаемое имя, PID, тип запуска, статус, двоичный файл, описание.
- Действия: пуск, стоп, смена типа запуска (включая «Авто отложенный» через `DelayedAutostart`), **удаление службы**.
- Фильтр «Подозрительные»: бинарник в пользовательских директориях / не найден, нет описания, авто-запуск но не работает.

### 5. Эвристика и файловые операции
- Анализ **недавно созданных/изменённых файлов** за N минут по выбранным корням (%TEMP%, Windows\Temp, ProgramData, Users\Public, Startup, Tasks…) — отслеживание активности малвари; исполняемые расширения помечаются эвристикой.
- Файловый менеджер с пакетными операциями: копирование, перемещение, **карантин** (переименование в `.vir` + манифест для восстановления), **принудительное удаление** заблокированных файлов (Restart Manager определяет блокирующие PID → завершение → удаление; фолбэк `MoveFileEx MOVEFILE_DELAY_UNTIL_REBOOT`), «Кто блокирует?».

### 6. Восстановление и снятие ограничений
| Действие | Ключи (соответствуют модулю RecoveryKit) |

| UAC | `EnableLUA=1`, `ConsentPromptBehaviorAdmin=5`, `PromptOnSecureDesktop=1` |
| «Выполнить» | `...\Policies\Explorer\NoRun` |

### 7. Системные действия
- **Безопасный режим** (`bcdedit /set {current} safeboot minimal|network`) и **возврат обычной загрузки**.
- Перезагрузка в **WinRE** (`shutdown /r /o`), в **UEFI/BIOS** (`shutdown /r /fw`), обычная перезагрузка/выключение.
- Быстрые вызовы: `diskmgmt.msc`, `taskmgr`, `msconfig`, `msinfo32`, Windows Update, Безопасность Windows, `reagentc /info`.

## Сборка

### Требования
- Windows 10/11 x64
- **.NET 8 SDK** ([скачать](https://dotnet.microsoft.com/download/dotnet/8.0)); проверить: `dotnet --list-sdks`

### Обычная сборка (для разработки)
```cmd
cd AegisKit
dotnet build AegisKit.sln -c Release
```
Результат: `src\AegisKit.App\bin\x64\Release\net8.0-windows\AegisKit.exe` (требует установленный .NET Desktop Runtime 8).
> Проект собран под `x64`; путь к результату задаётся свойством `Platform` в `.csproj`, поэтому `dotnet build` и `dotnet run` больше не расходятся по каталогам `bin\Release` и `bin\x64\Release`.

### Единый исполняемый файл (.exe, самодостаточный)
```cmd
dotnet publish src/AegisKit.App -c Release -r win-x64 --self-contained true ^
  -p:PublishSingleFile=true ^
  -p:IncludeNativeLibrariesForSelfExtract=true ^
  -p:EnableCompressionInSingleFile=true ^
  -o publish
```
Результат: **`publish\AegisKit.exe` (~63,5 МБ)** — ровно один файл, включающий .NET 8 + WPF, запускается на чистой Windows 10/11 без установки чего-либо и подходит для запуска из WinRE (графическая подсистема WinRE совместима с self-contained WPF).

> Параметризованный скрипт: `build.cmd` в корне проекта:
> `build.cmd` — обычная сборка, `build.cmd single` — один самодостаточный exe, `build.cmd selftest` — автоматическая проверка интерфейса.

### Самопроверка (рендер всех страниц без взаимодействия)
```cmd
build.cmd selftest
```
Скрипт собирает вариант без требования UAC (`-p:TestManifest=true`, `app_test.manifest`) и запускает его — иначе пришлось бы каждый раз подтверждать UAC:
```cmd
dotnet build src\AegisKit.App -c Release -p:TestManifest=true -p:BaseOutputPath=bin_test\
bin_test\x64\Release\net8.0-windows\AegisKit.exe --selftest --out:_selftest
```
Что получается в `_selftest`:
- `page_*.png` — снимок всего окна, `view_*.png` — только страницы;
- `layout_*.txt` — текстовая карта вёрстки (тип, имя, координаты, текст элемента) **с отчётом о наложениях** — по нему видно, что элементы не наезжают друг на друга;
- `journal.txt` — журнал приложения (предупреждения источников данных);
- `columns_*.txt` — список столбцов каждой таблицы с шириной, признаком «растягивать/перетаскивать» и отметкой обрезки. `ЗВЕЗДА (плохо)` в этом отчёте означает, что колонки снова нельзя двигать;
- `menu_actions.txt` / `menu_actions.png` — отчёт по открытому выпадающему меню (меню раскрывается принудительно, содержимое `Popup` попадает в карту вёрстки);
- `selftest.txt` — сводка «таблиц / строк» по страницам.

Код возврата 0 — все страницы отрисованы с данными; 2 — есть пустые страницы (подробности в `%TEMP%\aegiskit_selftest.log`).

## Архитектура

```
AegisKit/
├── AegisKit.sln
├── build.cmd                      ← сценарий сборки
└── src/
    ├── AegisKit.Core/             ← вся логика, без UI (net8.0-windows)
    │   ├── Native/NativeMethods.cs      P/Invoke: ntdll (NtSuspend/Resume/
    │   │                                NtSetInformationProcess), advapi32
    │   │                                (привилегии, RegLoadKey, SCM), wintrust
    │   │                                (WinVerifyTrust), rstrtmgr (Restart Manager)
    │   ├── Processes/                   ProcessService (WMI+Process, kill tree,
    │   │                                critical), SuspicionRules (эвристика)
    │   ├── Autostart/                   AutorunScanner — 20+ мест автозапуска
    │   ├── Registry/                    RegistryEditor (дерево/значения) +
    │   │                                RegistryHiveService (RegLoadKey offline)
    │   ├── Scheduler/                   TaskSchedulerService (PowerShell-бэкенд)
    │   ├── ServicesMan/                 ServiceManager (SCM API)
    │   ├── Files/                       RecentFilesScanner + FileOperations
    │   │                                (карантин, force-delete)
    │   ├── Recovery/                    RecoveryOps + RecoveryOps.Extra (все
    │   │                                repair-операции), RecoveryCatalog (список
    │   │                                пунктов), TempCleaner
    │   ├── AppSettings.cs               настройки интерфейса (JSON)
    │   ├── SystemOps/                   BootActions (bcdedit, shutdown, msc)
    │   └── Logging/SimpleLog.cs         журнал для UI
    └── AegisKit.App/              ← WPF-оболочка (net8.0-windows)
        ├── Themes/Dark.xaml             тёмная тема: палитра, стили DataGrid/
        │                                TreeView/кнопок/меню/прогресса
        ├── Common/                      RelayCommand, ViewModelBase, Ui-хелпер,
        │                                GridLayout (сохранение ширин столбцов)
        ├── Dialogs/InputDialog          универсальный диалог ввода
        └── Views/
            ├── MainWindow               боковая навигация + журнал + статус
            └── Pages/                   Processes, Autostart, Registry,
                                         Scheduler, Services, Files,
                                         Recovery, System
```

**Принципы**: модульность (UI не содержит логики — только привязки и вызовы Core); вся работа с системой — в фоновых потоках; эвристика единая (`SuspicionRules`); журнал всех операций с экспортом; приложение требует права администратора (`requireAdministrator` в манифесте — UAC запрашивается автоматически при запуске).

## Отличия от образца (RecoveryKit, Delphi/VCL)

| | RecoveryKit (образец) | AegisKit |
|---|---|---|
| Стек | Delphi/VCL, модули .pas | C#/.NET 8 + WPF, MVVM-lite |
| Сборка | RAD Studio (коммерч.) | `dotnet publish` → один exe, самодостаточный |
| Командные строки процессов | — | WMI в таблице процессов |
| Подписи Authenticode | выборочно | пакетно в процессах/автозапуске/службах |
| Планировщик | COM TLB | PowerShell-бэкенд с чекбоксами; фолбэк на `schtasks.exe` для WinRE, по умолчанию видна только выбранная папка |
| Службы | — | полный SCM-менеджер с эвристикой |
| Offline-кусты | RegLoadKey (uRegistryHiveLoader.pas) | то же + быстрый аудит SYSTEM-куста |
| Журнал | консоль отладки | панель внизу окна с процентами выполнения, экспортом в файл и очисткой |
| Восстановление | uTaskManager/uUac/uNoRun/uExplorerDrives/uFileAssociationRepair/uThemeRestore/uFontRestore | те же ключи + `uDisallowAndRestrict`, `uCAD`, `uPowerButton`, `uMouse`, `uDeviceManagerPage`, `uDesktopItems`, `uLogOff`, `uSwitchUser`, `uUserAccount`, `uCmdLine`, `uKeyboard` — и один клик «восстановить всё» с выбором пунктов |
| IFEO | `uIFEODebuggerCleaner` | то же + HKLM/HKCU, оба представления, `GlobalFlag`/`VerifierDlls`/`FilterFullPath`/`MitigationOptions` |

## Предупреждение

Инструмент изменяет реестр, службы, задачи и процессы. Используйте осознанно: подозрительное — не значит вредоносное (карантин и журнал помогут откатить действия). Запуск из WinRE — на свой риск, операции с офлайн-кустами делайте на копии файла куста.
